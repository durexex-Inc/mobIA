# TEC-182 — Opt-out: detecção, registro e silêncio — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** o lead pode pedir para não receber mais mensagens, o pedido é registrado como evidência de LGPD, e nenhum envio automático — presente ou futuro — alcança quem pediu para sair.

**Architecture:** detecção determinística por lista de termos em duas faixas de rigor; registro append-only em `optout_events`, estado atual = último evento; a proibição de envio mora em `GuardedOutbound.send`, para que todo caminho de envio a herde; uma checagem espelhada no início do turno evita pagar a classificação de um lead já silenciado.

**Tech Stack:** Python 3.13, SQLAlchemy 2 async, Alembic, Postgres, pytest + pytest-asyncio.

**Spec:** `docs/superpowers/specs/2026-09-01-tec-182-opt-out-design.md` — leia antes da Task 1. O plano argumenta a partir dela.

## Global Constraints

- **Sem acento em comentário, docstring ou identificador de Python.** É regra do repo (TEC-243). Markdown pode ter acento.
- **Nada de PII em log.** Nenhum evento de log carrega o texto do lead. Só ids, canal e nomes de classe. Ver `moderacao.entrada_bloqueada` como referência.
- **`ruff format` e `ruff check src tests alembic evals` e `mypy src` limpos** antes de cada commit. O CI roda `ruff format --check`, e um arquivo desformatado deixa a `main` vermelha.

```python
"""Deteccao do pedido de opt-out, e o texto que confirma ao lead.

RN-14.1 (SRS v1.0) lista "sair", "parar", "nao quero mais" e "descadastrar"
como palavras-chave. Aplicar isso como substring em qualquer posicao silencia
lead legitimo -- "podemos parar por aqui hoje?", "quero sair do aluguel e
comprar" -- e o erro e invisivel e permanente: o lead so ve o silencio.

Dai as duas faixas. A assimetria e o INVERSO da TEC-257: la marcar de mais era
o erro perigoso; aqui deixar de detectar um opt-out e violacao de LGPD e
detectar demais e prejuizo comercial. Por isso a faixa inequivoca e generosa e
so a ambigua e estrita.
"""

import re
import unicodedata

# Casam em qualquer posicao da mensagem. Nenhum destes aparece em fala de quem
# procura imovel, entao a posicao nao importa e o recall vale mais.
_TERMOS_INEQUIVOCOS: tuple[str, ...] = (
    "descadastrar",
    "descadastre",
    "nao quero mais receber",
    "pare de me mandar",
    "pare de mandar",
    "me tira da lista",
    "me tire da lista",
    "remover meu contato",
    "nao me mande mais",
)

# Casam SO quando sao a mensagem inteira normalizada. Todos aparecem em fala
# normal de quem procura imovel, e a mensagem de uma palavra so e o padrao real
# de quem quer sair.
_TERMOS_AMBIGUOS: frozenset[str] = frozenset(
    {"sair", "parar", "pare", "stop", "cancelar", "cancela"}
)

_SO_LETRAS_E_ESPACO = re.compile(r"[^a-z ]+")
_ESPACOS = re.compile(r"\s+")


def _normalizar(texto: str) -> str:
    """Minusculas, sem acento, sem pontuacao, espacos colapsados.

    Sem isso "PARAR!" e "Parar" escapariam da faixa estrita, que compara a
    mensagem inteira -- e sao exatamente a forma que um lead irritado escreve.
    """
    sem_acento = unicodedata.normalize("NFKD", texto.casefold())
    sem_acento = "".join(c for c in sem_acento if not unicodedata.combining(c))
    return _ESPACOS.sub(" ", _SO_LETRAS_E_ESPACO.sub(" ", sem_acento)).strip()


def pediu_optout(texto: str) -> bool:
    """O lead pediu para parar de receber mensagens.

    Determinstico e sem chamada paga: uma decisao de LGPD nao pode depender de
    um provedor estar de pe.
    """
    normalizado = _normalizar(texto)
    if not normalizado:
        return False
    if normalizado in _TERMOS_AMBIGUOS:
        return True
    return any(termo in normalizado for termo in _TERMOS_INEQUIVOCOS)


# Mora aqui, e nao em `turno.py`, pelo mesmo motivo que
# `TEXTO_DA_RECUSA_DE_ENTRADA` mora no modulo de moderacao: o texto pertence ao
# assunto, nao ao orquestrador que o entrega.
TEXTO_DA_CONFIRMACAO_DE_OPTOUT = (
    "Pronto, nao vou mais te enviar mensagens. Se mudar de ideia, e so falar "
    "com a nossa equipe. Obrigado pelo contato!"
)
```

Repare que `_normalizar` remove acento, então os termos da lista são escritos **sem acento** de propósito — `"nao quero mais receber"` casa com "não quero mais receber".

```python
"""O registro de opt-out, append-only.

Uma linha por evento, e o estado atual de um lead e o ULTIMO evento por
`(channel, conversation_key)`. Nao e coluna booleana de proposito: com booleano
a reativacao APAGA a evidencia do opt-out, que e o contrario do que a RN-14.2
pede -- ela exige o registro como prova de conformidade.

A linha referencia `message_id` e NAO copia o texto que disparou. O corpo ja
esta cifrado em `messages`; copia-lo criaria uma segunda copia em claro da fala
do lead. A RN-14.2 pede "o conteudo original que o disparou", e a referencia
**e** o conteudo original -- na versao que nao duplica dado pessoal.
"""

import uuid
from datetime import datetime

from sqlalchemy import DateTime, Index, String, Text
from sqlalchemy.dialects.postgresql import UUID as PgUUID
from sqlalchemy.orm import Mapped, mapped_column

from mobia.infra.db import Base

EVENTO_OPT_OUT = "OPT_OUT"
EVENTO_REATIVACAO = "REATIVACAO"


class OptoutEvent(Base):
    __tablename__ = "optout_events"

    id: Mapped[uuid.UUID] = mapped_column(PgUUID(as_uuid=True), primary_key=True)

    # O par que identifica o lead, o mesmo de `lead_qualification`.
    # `conversation_key` e o id externo do lead, invariante a direcao.
    channel: Mapped[str] = mapped_column(String(32), nullable=False)
    conversation_key: Mapped[str] = mapped_column(String(64), nullable=False)

    evento: Mapped[str] = mapped_column(String(16), nullable=False)

    # Nulo na reativacao: ela nao vem de mensagem nenhuma.
    message_id: Mapped[uuid.UUID | None] = mapped_column(PgUUID(as_uuid=True), nullable=True)

    # Nulos no opt-out: o ato e do lead, nao de um humano nosso.
    autor: Mapped[str | None] = mapped_column(String(120), nullable=True)
    motivo: Mapped[str | None] = mapped_column(Text, nullable=True)

    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), nullable=False)

    __table_args__ = (
        # A consulta quente e "qual o ultimo evento deste lead?", uma vez por
        # envio. DESC no indice para o LIMIT 1 nao ordenar em memoria. Mesmo
        # formato do `ix_messages_timeline`.
        Index(
            "ix_optout_events_lead",
            "channel",
            "conversation_key",
            created_at.desc(),
        ),
    )
```

```python
As duas escritas recebem `session_factory` e commitam sozinhas, como
`marcar_bloqueada`: sao atos completos em si, e quem chama nao tem transacao
para compartilhar. As duas leituras recebem `session` porque rodam dentro da
sessao de quem pergunta -- a guarda na porta de saida ja tem uma aberta.

import uuid
from datetime import UTC, datetime

from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker

from mobia.domain.messages.models import Message
from mobia.domain.optout.models import EVENTO_OPT_OUT, EVENTO_REATIVACAO, OptoutEvent


async def registrar_optout(
    session_factory: async_sessionmaker[AsyncSession],
    *,
    channel: str,
    conversation_key: str,
    message_id: uuid.UUID,
) -> None:
    """Acrescenta o evento de opt-out. Nunca atualiza nada."""
    async with session_factory() as session:
        session.add(
            OptoutEvent(
                id=uuid.uuid4(),
                channel=channel,
                conversation_key=conversation_key,
                evento=EVENTO_OPT_OUT,
                message_id=message_id,
                created_at=datetime.now(UTC),
            )
        )
        await session.commit()

    session_factory: async_sessionmaker[AsyncSession],
    *,
    channel: str,
    conversation_key: str,
    autor: str,
    motivo: str,

    """Acrescenta o evento de reativacao, com quem mandou e por que.

    `autor` e `motivo` nao tem default: a RN-14.3 exige justificativa, e um
    default vazio a tornaria decorativa.

    async with session_factory() as session:
        session.add(
            OptoutEvent(
                id=uuid.uuid4(),
                channel=channel,
                conversation_key=conversation_key,
                evento=EVENTO_REATIVACAO,
                autor=autor,
                motivo=motivo,
                created_at=datetime.now(UTC),

        )
        await session.commit()


async def esta_em_optout(
    session: AsyncSession, *, channel: str, conversation_key: str
) -> bool:
    """O ultimo evento deste lead e um opt-out.

    Sem evento nenhum, nao esta -- o estado default e "pode receber".
    """
    ultimo = (
        await session.execute(
            select(OptoutEvent.evento)
            .where(
                OptoutEvent.channel == channel,
                OptoutEvent.conversation_key == conversation_key,
            )
            .order_by(OptoutEvent.created_at.desc())
            .limit(1)
        )
    ).scalar_one_or_none()
    return ultimo == EVENTO_OPT_OUT


async def esta_em_optout_por_mensagem(session: AsyncSession, message_id: uuid.UUID) -> bool:
    """A mesma pergunta, para quem so tem o id da mensagem.

    E o caso da guarda em `GuardedOutbound.send`, cuja assinatura nao carrega o
    par do lead. Mensagem inexistente devolve False: se nao ha lead, nao ha
    opt-out a respeitar, e recusar o envio por isso esconderia o defeito real.
    """
    lead = (
        await session.execute(
            select(Message.channel, Message.conversation_key).where(Message.id == message_id)
        )
    ).one_or_none()
    if lead is None:
        return False
    return await esta_em_optout(session, channel=lead.channel, conversation_key=lead.conversation_key)
```
